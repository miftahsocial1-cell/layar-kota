# Domain docs

This repo uses a single context. Before exploring the codebase, read the root `GLOSSARY.md` and the relevant decision records in `docs/adr/`, when present. Continue if either is absent. The domain-modeling skill adds these files as terms and decisions are settled.

Use glossary terms in tickets, proposals, hypotheses, and tests. Record genuine vocabulary gaps for domain modeling. If a proposal conflicts with an existing decision record, cite it and explain why the decision is worth revisiting.
